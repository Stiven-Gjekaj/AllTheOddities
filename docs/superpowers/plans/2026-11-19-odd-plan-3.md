# odd, plan 3: wifi-pass, firewall, share, expose, carry, remote

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add six oddities to `odd`: `wifi-pass`, `firewall`, `share`,
`expose`, `carry` and `remote`.

**Architecture:** As plan 2. `src/qr.rs` draws a QR code in the terminal for
`wifi-pass` and `share`. `odd share` serves files with a small HTTP server on
`std::net`. `odd expose` and `odd carry` drive the Tailscale CLI, which
`ssh::tailscale::cli` finds.

**Tech Stack:** as plan 1, plus `qrcode` (no default features: pure Rust, no
image code) and `getrandom` (the random token of `odd share`).

**Spec:** `docs/superpowers/specs/2026-11-19-odd-design.md` (section 7 and 7.2).

## Global Constraints

- All Global Constraints of plans 1 and 2 apply.
- A new dependency is a commit of its own, and compiles no C.

## Review Focus

1. A request of `odd share` for `../` or for a path outside the shared
   folder. It gets 404, and no byte outside the folder. Test in Task 3.
2. A request without the token. It gets 404. Test in Task 3.
3. A Wi-Fi name with `;`, `,`, `:`, `\` or `"`. The QR text escapes it, so a
   phone reads the correct network. Test in Task 1.
4. `odd carry` with no file named. It never sends a private key. Test in
   Task 5.
5. Windows Home for `odd remote`. It exits 2 before a change. Test in Task 6.

### Task 0: QR codes

Add `qrcode = { version = "=0.15.0", default-features = false, features = ["std"] }`
and `getrandom = "=0.4.3"` in one commit. Then `src/qr.rs`:
`pub fn render(text: &str) -> String`, which draws the code with the half
blocks `▀ ▄ █` and a quiet zone of 2 modules, two rows of modules in one line
of text. Tests: `render_is_square_in_modules` (for a short text, each line
has the same width, and the width equals the module count plus the quiet
zone), `render_of_the_same_text_is_the_same`.

### Task 1: `odd wifi-pass`

Hosts: all. Admin: no (macOS asks for the keychain itself; Linux may need
root to read secrets). Undo: no.

`odd wifi-pass [<network>] [--qr]`. With no network, the current one.

| Host | The current network | The password |
| :-- | :-- | :-- |
| macOS | `ipconfig getsummary <wifi device>` line `SSID : <name>`; the Wi-Fi device from `networksetup -listallhardwareports` | `security find-generic-password -D "AirPort network password" -a <name> -w` (interactive: macOS asks) |
| Linux | `nmcli -t -f active,ssid dev wifi`, the line `yes:<name>` | `nmcli -s -g 802-11-wireless-security.psk connection show <name>` |
| Windows | `netsh wlan show interfaces`, the line `SSID : <name>` | `netsh wlan show profile name=<name> key=clear`, the line `Key Content : <password>` |

`wifi_qr_text(ssid, password) -> String` gives
`WIFI:T:WPA;S:<ssid>;P:<password>;;`, with `\`, `;`, `,`, `:` and `"`
escaped by a `\`. An open network (no password) gives `WIFI:T:nopass;S:<ssid>;;`.
Tests: `escapes_special_characters`, `an_open_network_has_nopass`,
`macos_reads_the_ssid_of_the_wifi_device`, `linux_reads_the_active_network`,
`windows_reads_the_key_content`, `no_wifi_fails_with_a_message`,
`qr_prints_a_code`.

### Task 2: `odd firewall`

Hosts: Windows, Linux. Admin: yes. Undo: yes.

`odd firewall open <port> [--udp]`, `odd firewall close <port> [--udp]`,
`odd firewall list`. The port is 1 to 65535.

- Windows: `netsh advfirewall firewall add rule name=odd-<port>-<tcp|udp>
  dir=in action=allow protocol=<TCP|UDP> localport=<port>`; close deletes
  that rule. Undo of open deletes it.
- Linux: ufw when `ufw status` says `Status: active`: `ufw allow <port>/<proto>`,
  close `ufw delete allow <port>/<proto>`. Else firewalld when
  `firewall-cmd --state` gives `running`: `firewall-cmd --permanent
  --add-port=<port>/<proto>` then `firewall-cmd --reload`; close with
  `--remove-port`. Else: "No firewall runs, so the port is open already."
- `list` prints the ports that the record of `odd` holds.
- Tests: `a_bad_port_exits_2`, `windows_adds_a_named_rule`,
  `linux_uses_ufw_when_it_is_active`, `linux_uses_firewalld_else`,
  `linux_with_no_firewall_changes_nothing`, `undo_closes_the_port`.

### Task 3: `odd share`

Hosts: all. Admin: no. Undo: no.

`odd share <path> [--port <n>]`. It serves the file or the folder until
Ctrl+C, at `http://<address of this computer>:<port>/<token>/`.

- The token is 16 random bytes as hex, from `getrandom`.
- The address is the local address of a UDP socket connected to `1.1.1.1:80`
  (no packet goes out). `--port 0` (the default) takes a free port.
- `serve(listener, root, token, stop)` answers GET only, with HTTP/1.0 and
  `Connection: close`. `/<token>/` of a folder gives an HTML list of its
  entries. `/<token>/<path>` gives the file. Each other path gives 404. A
  path resolves inside the root only: `..`, a full path and a link out of the
  root give 404.
- It prints the URL, and its QR code.
- Tests (each with a server on `127.0.0.1:0` in a thread, and a request on a
  `TcpStream`): `a_file_is_served`, `a_folder_is_listed`,
  `no_token_gives_404`, `dot_dot_gives_404`, `a_single_file_share_serves_only_that_file`,
  `the_token_is_32_hex_characters`.

### Task 4: `odd expose`

Hosts: all. Admin: no. Undo: no.

`odd expose <port> [--public]`. It runs `tailscale serve <port>`, or
`tailscale funnel <port>` with `--public`, on the terminal, so Tailscale
prints the URL, and Ctrl+C stops it. No Tailscale: "Run odd ssh --tailscale
first." and exit 1. A bad port exits 2.
Tests: `serve_runs_on_the_tailnet`, `public_runs_funnel`,
`no_tailscale_fails`, `a_bad_port_exits_2`.

### Task 5: `odd carry`

Hosts: all. Admin: no. Undo: yes (for `receive --apply`).

- `odd carry send <computer> [<file>...]`: with no file, the files of the
  home directory that exist from this list: `.ssh/config`, `.gitconfig`,
  `.gitconfig-*`, `.profile`, `.zprofile`, `.bashrc`, `.zshrc`. A private key
  goes only when the person names it. It packs them with
  `tar -cf <tmp>/odd-carry.tar -C <home> <paths>`, and runs
  `tailscale file cp <tar> <computer>:`.
- `odd carry receive [--apply]`: runs `tailscale file get --wait
  <staging>`, with the staging folder `~/.local/state/odd/carry`
  (`%LOCALAPPDATA%\odd\state\carry`), unpacks each `odd-carry*.tar` there with
  `tar -xf`, and lists the files. With `--apply`, it copies each file into the
  home directory, and records the text before for undo.
- Tests: `send_takes_the_default_files_that_exist`,
  `send_never_takes_a_private_key_by_default`, `send_runs_tar_then_taildrop`,
  `receive_lists_the_files`, `apply_copies_and_undo_puts_back`.

### Task 6: `odd remote`

Hosts: all. Admin: macOS and Windows. Undo: yes.

| Host | What it turns on | Undo |
| :-- | :-- | :-- |
| macOS | Screen Sharing: `launchctl load -w /System/Library/LaunchDaemons/com.apple.screensharing.plist` | `launchctl unload -w` of the same file |
| Windows | `fDenyTSConnections` = 0 in `HKLM\SYSTEM\CurrentControlSet\Control\Terminal Server`, and the firewall rule with the name `RemoteDesktop-UserMode-In-TCP` (the name is the same in each language) | The value before, and `Disable-NetFirewallRule` |
| Linux | GNOME Remote Desktop: `grdctl rdp enable`. It tells the person to set the user name and the password in Settings, because `grdctl` takes them only on the command line. | `grdctl rdp disable` |

Windows Home (`EditionID` `Core` in `HKLM\SOFTWARE\Microsoft\Windows NT\CurrentVersion`)
has no Remote Desktop server: exit 2 before a change. Linux without `grdctl`:
exit 1 with a message.
Tests: `windows_home_exits_2`, `windows_turns_on_rdp_and_the_rule`,
`macos_loads_screen_sharing`, `linux_without_grdctl_fails`,
`undo_turns_it_off`.
