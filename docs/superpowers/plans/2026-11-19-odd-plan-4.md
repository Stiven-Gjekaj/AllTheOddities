> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add the last six oddities, so that `odd` has the 20 of the first
release, and prepare the first release.

**Architecture:** As plans 2 and 3. `Ctx` gets `copy_file` and `remove_dir`,
both aware of `--dry-run`.

**Tech Stack:** as plan 1, plus `toml` (pure Rust) for `apps.toml`. The host
gives `openssl` (`odd devcert`) and `tar` (`odd font`).

**Spec:** `docs/superpowers/specs/2026-11-19-odd-design.md` (section 7, 7.2, 8).

## Global Constraints

- All Global Constraints of plans 1 to 3 apply.
- No dependency compiles C. So `odd devcert` uses the `openssl` of the host,
  not a Rust certificate library (they use `ring`, which compiles C).

### Task 0: `Ctx::copy_file` and `Ctx::remove_dir`

`copy_file(from, to)` copies bytes and makes the folders of `to`.
`remove_dir(path)` deletes a folder and each thing in it, and deletes a link
as a link (`symlink_metadata`), never its target. Both print a "would" line
in dry-run. Tests: `copy_file_copies_bytes`, `remove_dir_keeps_the_target_of_a_link`,
`dry_run_copies_and_removes_nothing`.

### Task 1: `odd font`

Hosts: all. Admin: no. Undo: yes.

`odd font <file | folder | archive | Nerd Font name>`.

- A name with no `/`, `\` and no extension is a Nerd Font: on macOS and
  Windows `https://github.com/ryanoasis/nerd-fonts/releases/latest/download/<Name>.zip`,
  on Linux `<Name>.tar.xz`. `odd` downloads it with `ctx.http`, and unpacks
  it with `tar -xf <archive> -C <folder>` (bsdtar of macOS and Windows reads
  zip; GNU tar of Linux reads tar.xz).
- It installs each `.ttf` and `.otf` that it finds, in folders too:
  macOS `~/Library/Fonts`, Linux `~/.local/share/fonts` then `fc-cache -f`,
  Windows `%LOCALAPPDATA%\Microsoft\Windows\Fonts` and the value
  `<file name without extension> (TrueType)` = the path in
  `HKCU\Software\Microsoft\Windows NT\CurrentVersion\Fonts`.
- A font file that is there already is skipped. Undo deletes each file that
  `odd` copied (RestoreFile with no text before), and the registry values.
- Tests: `a_name_downloads_the_nerd_font`, `linux_uses_tar_xz_and_fc_cache`,
  `finds_fonts_in_folders`, `windows_registers_each_font`,
  `a_font_that_is_there_is_skipped`, `undo_deletes_the_copied_files`.

### Task 2: `odd devcert`

Hosts: all. Admin: macOS and Linux. Undo: yes.

`odd devcert [<extra name>...]` makes, in `~/.local/share/odd/devcert`
(`%LOCALAPPDATA%\odd\devcert`):

1. `ca.key` and `ca.pem`, a P-256 authority named `odd devcert CA`, for 10
   years, if they do not exist:
   `openssl req -x509 -new -newkey ec -pkeyopt ec_paramgen_curve:prime256v1 -nodes -keyout ca.key -out ca.pem -days 3650 -subj "/CN=odd devcert CA" -addext basicConstraints=critical,CA:TRUE -addext keyUsage=critical,keyCertSign,cRLSign`.
2. `localhost.key` and `localhost.pem` for `localhost`, `127.0.0.1`, `::1` and
   each extra name, for 825 days: `openssl req -new ... -keyout localhost.key -out localhost.csr -subj /CN=localhost`,
   then `openssl x509 -req -in localhost.csr -CA ca.pem -CAkey ca.key -CAcreateserial -out localhost.pem -days 825 -extfile ext.cnf`,
   with `ext.cnf` holding `subjectAltName` and `extendedKeyUsage=serverAuth`.
3. Makes the host trust `ca.pem`: macOS `security add-trusted-cert -d -r trustRoot -k /Library/Keychains/System.keychain ca.pem`;
   Linux `/usr/local/share/ca-certificates/odd-devcert.crt` then
   `update-ca-certificates` when that command exists, else
   `/etc/pki/ca-trust/source/anchors/odd-devcert.pem` then `update-ca-trust`;
   Windows `certutil -user -addstore Root ca.pem` (Windows asks the person).
4. Prints the paths of `localhost.pem` and `localhost.key`.

The `openssl` is the one on PATH, or on Windows
`C:\Program Files\Git\usr\bin\openssl.exe`. None: exit 1 with "Install
openssl (Git for Windows has one), then run odd devcert again." Undo removes
the trust (`security delete-certificate -c "odd devcert CA" ...`, the file and
the update command, `certutil -user -delstore Root "odd devcert CA"`). The
files stay, so a server that uses them keeps working.
Tests: `no_openssl_fails`, `makes_the_ca_once`, `the_names_go_in_the_san`,
`macos_trusts_in_the_system_keychain`, `linux_debian_and_fedora_trust`,
`windows_trusts_in_the_user_store`, `undo_removes_the_trust`.

### Task 3: `odd autostart`

Hosts: all. Admin: no. Undo: yes.

`odd autostart add <name> -- <command> [args...]`, `remove <name>`, `list`.
The name has letters, digits, `-` and `_`.

| Host | What `add` makes |
| :-- | :-- |
| macOS | `~/Library/LaunchAgents/com.odd.<name>.plist` with `ProgramArguments` (each argument an XML-escaped `<string>`) and `RunAtLoad`, then `launchctl load -w` |
| Linux | `~/.config/systemd/user/odd-<name>.service` with `ExecStart=` (each argument in double quotes, `\` `"` `$` `%` escaped) and `WantedBy=default.target`, then `systemctl --user daemon-reload` and `enable --now` |
| Windows | The value `odd-<name>` in `HKCU\Software\Microsoft\Windows\CurrentVersion\Run`: the command line, each argument with a space in double quotes |

`remove` and undo reverse each one. `list` prints the names.
Tests: `macos_writes_a_launch_agent`, `linux_writes_a_user_unit`,
`windows_writes_the_run_value`, `a_command_with_spaces_stays_whole`,
`a_bad_name_exits_2`, `remove_undoes_add`, `list_shows_the_names`.

### Task 4: `odd cache-purge`

Hosts: all. Admin: no. Undo: no.

`odd cache-purge` lists the caches of developer tools that exist, with the
size and the number of files, then asks for each one (default no).
`--all` takes each one, and `--only <name>` selects. `--list` only lists.

| Name | macOS | Linux | Windows |
| :-- | :-- | :-- | :-- |
| npm | `~/.npm/_cacache` | `~/.npm/_cacache` | `%LOCALAPPDATA%\npm-cache\_cacache` |
| pnpm | `~/Library/pnpm/store` | `~/.local/share/pnpm/store` | `%LOCALAPPDATA%\pnpm\store` |
| yarn | `~/Library/Caches/Yarn` | `~/.cache/yarn` | `%LOCALAPPDATA%\Yarn\Cache` |
| pip | `~/Library/Caches/pip` | `~/.cache/pip` | `%LOCALAPPDATA%\pip\Cache` |
| cargo | `~/.cargo/registry/cache` | same | same, in `%USERPROFILE%` |
| go | `~/Library/Caches/go-build` | `~/.cache/go-build` | `%LOCALAPPDATA%\go-build` |
| gradle | `~/.gradle/caches` | same | same |
| xcode | `~/Library/Developer/Xcode/DerivedData` | | |
| homebrew | `~/Library/Caches/Homebrew` | | |

The size counts files, not links, and does not follow a link. `odd` deletes
the cache folder with `Ctx::remove_dir`.
Tests: `lists_only_caches_that_exist`, `size_does_not_follow_links`,
`all_deletes_each_cache`, `only_selects`, `a_no_keeps_the_cache`,
`a_link_in_a_cache_keeps_its_target`.

### Task 5: `odd apps`

Hosts: all. Admin: Linux. Undo: no.

Add `toml = "=1.2.1"` in its own commit (pure Rust).

`odd apps install`, `odd apps list`, `odd apps catalog`, `odd apps init`.

- The file is `~/.config/odd/apps.toml` (`%APPDATA%\odd\apps.toml`):
  `apps = ["git", "vscode"]`, and `[custom.<name>]` tables with the keys
  `brew`, `cask`, `winget`, `apt`, `dnf`, `pacman`.
- The catalog has: git, gh, vscode, firefox, chrome, nodejs, python, rustup,
  ripgrep, fd, jq, neovim, tmux, vlc, obsidian, tailscale. A custom table of
  the same name wins.
- The manager: macOS Homebrew (`brew`, or `cask` with `--cask`); with no
  `brew`, `odd` asks, then runs the official install script on the terminal.
  Linux: apt-get, dnf or pacman by distribution (as `odd ssh --in`). Windows:
  winget `install --id <id> -e --accept-source-agreements --accept-package-agreements`.
- An app with no id for this manager is named and skipped. An app that is
  installed (`brew list`, `dpkg -s`, `rpm -q`, `pacman -Q`,
  `winget list --id <id> -e`) is skipped.
- `init` writes a file with `apps = ["git", "gh"]` if there is none.
- Tests: `install_uses_the_manager_of_the_host`, `custom_wins_over_the_catalog`,
  `an_unknown_app_is_named_and_skipped`, `an_installed_app_is_skipped`,
  `cask_apps_use_cask`, `linux_needs_admin`, `init_writes_a_file_once`.

### Task 6: `odd dualboot-clock`

Hosts: Windows, Linux. Admin: yes. Undo: yes.

- Windows: `RealTimeIsUniversal` = 1 (REG_DWORD) in
  `HKLM\SYSTEM\CurrentControlSet\Control\TimeZoneInformation`. Undo with
  `winreg::undo_step`.
- Linux: with `--linux-local`, `timedatectl set-local-rtc 1 --adjust-system-clock`;
  undo `set-local-rtc 0`. With no flag: "Run odd dualboot-clock on Windows.
  One side is enough. Or run odd dualboot-clock --linux-local here." and
  exit 0 with no change.
- Tests: `windows_sets_universal_time`, `linux_without_the_flag_changes_nothing`,
  `linux_local_sets_the_rtc`, `undo_puts_it_back`.
