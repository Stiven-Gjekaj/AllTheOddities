# odd, plan 2: git, env, tweaks, hostname, hosts, dns

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add six oddities to `odd`: `git`, `env`, `tweaks`, `hostname`,
`hosts` and `dns`.

**Architecture:** Each oddity is one file in `src/oddities/`, one line in
`ODDITIES`, and uses the core of plan 1 only: `Ctx` (`query`, `change`,
`write_file`, `sys_path`), `state::record` / `state::upsert_block`, and the
`Oddity` trait. Each test uses `TestCtx` with a `FakeRunner`.

**Tech Stack:** as plan 1. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-19-odd-design.md` (section 7 and 7.2).

## Global Constraints

- All of plan 1's Global Constraints apply.
- Work on `main`. Push `main` after each task, and check that CI passes.
- Each new oddity has the label `experimental`, and the hosts that the table
  of each task gives.
- A step that needs an administrator makes `needs_admin` true, so `odd` stops
  before the first change.

## Review Focus

1. A Windows registry value that does not exist before `odd` sets it. Undo
   deletes it, and does not write an empty value. Test in Task 2 and Task 3.
2. A value with a space, a quote or a `$` (an env value, a path of a git
   folder). It reaches the file or the command whole. Test in Task 1 and
   Task 2.
3. A hosts file or a profile that the person changed after `odd` wrote it.
   Undo removes only the block of `odd`. Test in Task 5.
4. A name that the host refuses: a hostname with a space or 16 characters on
   Windows. `odd` refuses it before a change. Test in Task 4.
5. A Linux without NetworkManager for `odd dns`. `odd` says so, and changes
   nothing. Test in Task 6.

### Task 1: `odd git`

Hosts: all. Admin: no. Undo: yes.

`odd git add <folder> --name <name> --email <email> [--sign]` and
`odd git list`.

- The folder must exist. `odd` makes it full, uses forward slashes, and ends
  it with `/`.
- It writes `~/.gitconfig-<last part of the folder>` with `[user] name`,
  `email`; with `--sign` also `[gpg] format = ssh`, `[user] signingkey =
  <~/.ssh/id_ed25519.pub>`, `[commit] gpgsign = true`, `[tag] gpgsign = true`,
  `[gpg "ssh"] allowedSignersFile = ~/.ssh/allowed_signers`, and adds the line
  `<email> namespaces="git" <public key>` to `~/.ssh/allowed_signers`.
- It adds `[includeIf "gitdir/i:<folder>/"] path = <file>` (`gitdir:` on
  Linux, which has case-sensitive paths) to a block named `git` of
  `~/.gitconfig`. One block holds each folder.
- `--sign` with no public key stops with "Run odd ssh --out first."
- A value goes in double quotes, with `\` and `"` escaped, as git reads them.
- `list` prints each folder of the block, and the name and email of its file.
- Tests: `add_writes_the_profile_and_the_include`,
  `a_second_folder_joins_the_block`, `the_same_folder_twice_writes_one_include`,
  `a_value_with_a_quote_is_escaped`, `sign_needs_a_public_key`,
  `sign_adds_the_allowed_signer`, `linux_uses_gitdir_and_others_gitdir_i`,
  `undo_removes_the_block_and_the_file`.

### Task 2: `odd env`

Hosts: all. Admin: no. Undo: yes.

`odd env set <NAME> <value>` and `odd env list`.

- The name must match `[A-Za-z_][A-Za-z0-9_]*`. Else exit 2.
- macOS and Linux: a block named `env` in the profiles of `profile::profiles`,
  with one line `export NAME='value'` for each name. A `'` in the value
  becomes `'\''`. A second `set` of a name replaces its line. fish:
  `set -Ux NAME value` through `fish -c` with fish quotes, undo
  `set -Ue NAME`.
- Windows: `reg add HKCU\Environment /v NAME /t REG_SZ /d value /f`, then
  `broadcast_change`. Undo with `winreg::undo_step`.
- `list` prints the names of the block (unix) or of the record (Windows).
- Tests: `set_writes_an_export_line`, `a_second_set_replaces_the_line`,
  `a_quote_in_the_value_survives`, `a_bad_name_exits_2`,
  `windows_sets_the_user_value`, `windows_undo_deletes_a_new_value`,
  `windows_undo_puts_back_the_old_value`.

### Task 3: `odd tweaks`

Hosts: all. Admin: for some tweaks. Undo: yes.

`odd tweaks` lists the tweaks of the host with their state (`on`, `off`).
`odd tweaks apply [--only <name>...]` turns them on. With a tweak that needs
an administrator and no administrator, `apply` exits 3, unless
`--user-only` skips those tweaks.

| Host | Name | Admin | Setting | On |
| :-- | :-- | :-- | :-- | :-- |
| Windows | file-extensions | no | `HKCU\Software\Microsoft\Windows\CurrentVersion\Explorer\Advanced` `HideFileExt` DWORD | 0 |
| Windows | hidden-files | no | same key, `Hidden` DWORD | 1 |
| Windows | long-paths | yes | `HKLM\SYSTEM\CurrentControlSet\Control\FileSystem` `LongPathsEnabled` DWORD | 1 |
| Windows | developer-mode | yes | `HKLM\SOFTWARE\Microsoft\Windows\CurrentVersion\AppModelUnlock` `AllowDevelopmentWithoutDevLicense` DWORD | 1 |
| macOS | hidden-files | no | `defaults` `com.apple.finder` `AppleShowAllFiles` bool | true |
| macOS | key-repeat | no | `NSGlobalDomain` `KeyRepeat` int 2 and `InitialKeyRepeat` int 15 | 2 / 15 |
| Linux | inotify-watches | yes | `/etc/sysctl.d/90-odd.conf`: `fs.inotify.max_user_watches = 524288`, then `sysctl --system` | 524288 |

- A tweak that is on already changes nothing and records nothing.
- Undo puts back the value before, or deletes a value that did not exist.
- macOS restarts Finder with `killall Finder` after `hidden-files`, and says
  that key repeat needs a new login.
- Tests: `list_shows_the_state_of_each_tweak`,
  `apply_sets_only_the_tweaks_that_are_off`, `admin_tweak_without_admin_exits_3`,
  `user_only_skips_admin_tweaks`, `only_selects_tweaks`,
  `windows_undo_deletes_a_value_that_did_not_exist`,
  `macos_undo_puts_back_the_old_value`, `linux_writes_the_sysctl_file`.

### Task 4: `odd hostname`

Hosts: all. Admin: yes. Undo: yes.

`odd hostname <name>` and `odd hostname` (prints the names).

- The name has 1 to 63 letters, digits and hyphens, and does not start or
  end with a hyphen. On Windows, it has at most 15 characters. Else exit 2
  before a change.
- macOS: `scutil --set ComputerName`, `--set LocalHostName`, `--set HostName`.
  Undo sets each one back from `scutil --get` (a name that was not set stays
  set; `docs/limits.md` says so).
- Linux: `hostnamectl set-hostname <name>`, and in `/etc/hosts` each line
  `127.0.1.1 <old>` becomes `127.0.1.1 <name>` (RestoreFile).
- Windows: `powershell -NoProfile -Command Rename-Computer -NewName '<name>' -Force`,
  and says that the new name comes after a restart.
- Tests: `a_name_with_a_space_exits_2`, `windows_refuses_16_characters`,
  `macos_sets_three_names`, `linux_updates_etc_hosts`,
  `undo_sets_the_old_name_back`.

### Task 5: `odd hosts`

Hosts: all. Admin: yes (`list` no). Undo: yes.

`odd hosts add <ip> <name>...`, `odd hosts remove <name>`, `odd hosts list`.

- The file is `/etc/hosts`, or `C:\Windows\System32\drivers\etc\hosts`
  (through `sys_path`). Each entry of `odd` goes in a block named `hosts`.
- The ip must parse as `std::net::IpAddr`; each name as a hostname. Else
  exit 2.
- `add` of a name that the block has replaces its line. `remove` takes the
  name out of the block, and removes a line with no name left.
- `list` prints the lines of the block.
- Tests: `add_writes_the_block`, `add_of_a_name_again_replaces_its_line`,
  `remove_takes_the_name_out`, `a_bad_ip_exits_2`,
  `undo_keeps_the_lines_of_the_person` (a line the person added after `odd`
  stays).

### Task 6: `odd dns`

Hosts: all. Admin: yes (`show` no). Undo: yes.

`odd dns set <preset or address...>`, `odd dns reset`, `odd dns show`.
Presets: `cloudflare` 1.1.1.1 1.0.0.1, `google` 8.8.8.8 8.8.4.4, `quad9`
9.9.9.9 149.112.112.112.

- macOS: the service of the default route: `route -n get default` gives the
  interface, `networksetup -listallhardwareports` gives its service.
  `networksetup -getdnsservers <service>` reads, `-setdnsservers <service>
  <ips>` or `Empty` sets.
- Linux: NetworkManager only. The device of `ip route show default`, its
  connection from `nmcli -t -f NAME,DEVICE connection show --active`.
  `nmcli -g ipv4.dns,ipv4.ignore-auto-dns connection show <conn>` reads;
  `nmcli connection modify <conn> ipv4.dns "<ips>" ipv4.ignore-auto-dns yes`
  then `nmcli connection up <conn>` sets. No `nmcli`: stop with exit 1 and
  "odd dns needs NetworkManager on Linux."
- Windows: one PowerShell line gives the index of the interface of the
  default route, and its static name servers from the registry key of its
  GUID (empty means DHCP). `Set-DnsClientServerAddress -InterfaceIndex <n>
  -ServerAddresses (...)` sets; `-ResetServerAddresses` resets.
- Undo puts back the servers before, or DHCP when there were none.
- Tests: `preset_names_give_the_addresses`, `a_bad_address_exits_2`,
  `macos_sets_the_service_of_the_default_route`,
  `linux_without_nmcli_changes_nothing`, `linux_sets_the_active_connection`,
  `windows_sets_the_default_interface`, `undo_goes_back_to_dhcp`.
